# ADR-0002：做减法，只保留跨宿主核心

- 状态：已决定
- 日期：2026-10-23
- 替代：ADR-0001（已删除，见 Git 历史）的迁移阶段与任务分诊；其决定 1B、2A 并入本 ADR
- 来源：T-000027 补充，维护者原话「我是想做非宿主绑定的AI辅助开发工程化管理脚手架，现在看起来好像风险挺多，需要优化设计来降低风险，或者删除没用的功能来降低风险」；决策方式：维护者「好像比较复杂，根据阅读本地参考博客目录里的博客（图文都要阅读），你帮我做决策吧」

## 1. 判定标准

一项机制要保留，须满足：

1. **跨宿主核心需要**：Codex、opencode、DeepSeek Harness、Claude Code 中断续做时依赖它；
2. **有价值证据**：本仓库记录显示它拦下过真实问题，或维护者明确要求过，或参考博客中有实践数据支持；
3. **检查结构或客观信号，不判断自然语言**：脚本只判断文件、字段、编号、命令结果、状态是否存在与一致；措辞与方案质量交给独立审查和人。

参考博客（`本地参考博客目录`，作为外部资料，只取事实与原则）提炼出的依据：

| 编号 | 原则 | 出处 |
| :-- | :-- | :-- |
| B1 | 「能用工具确定性检查的，交给工具；需要理解和判断的，交给 AI；只有反复出现、又无法工具化的行为约束，才写成规则」；规则越多注意力越稀释（800 行 Skill 反而更不听话） | 《给AI写了800行规则，它反而更不听话了》 |
| B2 | 门禁看「骗不过的客观信号」（`check: command` 而非 `check: exists`）；成本包络每类循环 ≤3，触顶交人；软约束（提示词、配置）模型改得动，强制点要放在模型改不动的地方 | 《AI工程化防翻车指南》 |
| B3 | 含糊词、死链等文档问题由 AI 独立审查扫出，人判断需求合不合理；阈值放在独立红线配置，改动触发门禁等人确认；「已完成」必须可程序验证（输出是 X 则通过）；进度存文件，只能用命令推进 | 《3 个月用Harness重构90万行旧项目》 |
| B4 | 需求放行看四项必答（做什么、为谁做、关键业务规则、验收标准）；改善即批准；知识库要有老化退场，过期知识比没有更危险 | 《别只盯着AI Coding，真正的变化发生在整个研发流程》 |
| B5 | 知识分三层：代码事实交给工具，模块文档只写「为什么」，记忆由 AI 捕获并晋升到模块文档；PRD 覆盖矩阵与「三道闸」（拆分出口：任务必须引用设计章节）拦住转述失真 | 《给AI写了800行规则，它反而更不听话了》 |
| B6 | 流程是手段：当某个环节变得多余，就该拆掉；x-flow 15 个版本中持续删减不适合的内容 | 《别只盯着AI Coding…》《给AI写了800行规则…》 |

## 3. 决定

### 3.1 保留

| # | 功能 | 位置 | 依据 |
| :-- | :-- | :-- | :-- |
| K1 | Spec 三件套模板与新建 | `ai-new-spec.sh`、模板 | 接力载体（B3「每步产出落盘」） |
| K2 | 门记录 check / pass / status / reset、`.gates`、`.violations` | `ai-gate.sh` 主干 | B3「进度存文件，只能用命令推进」 |
| K3 | 角色接手 owner / worker / review | `ai-resume.sh` | 跨会话、跨宿主恢复 |
| K4 | 正式验证、`verification.md`、状态指纹（全仓模式） | `ai-verify.sh`、`ai-state-id.sh` | B2 客观信号；B3「已完成」可程序验证 |
| K5 | 验证连续失败计数（黄卡） | `ai-verify.sh` | B2 成本包络 ≤3（草案曾建议删除，按 B2 改为保留） |
| K6 | G1 四项必答、原话、待确认清零、象限与分级依据 | `ck_g1` | B4 四项放行条件；四象限决定谁做 G6 |
| K7 | G2 AC 表结构（编号、通过 / 不通过、无空单元格） | `ck_g2` | B3「把什么算通过、什么算不过都写清楚」 |
| K8 | G3 结构检查：依赖序、检查点、影响面、检索依据、模块登记、②③前置决策与边界样本 | `ck_g3` | B4 施工图式方案；结构检查无误报记录 |
| K9 | 需求追溯：G3 覆盖矩阵与 G4 任务引用设计章节 | `ck_trace_g3` / `ck_trace_g4` | B5 PRD 覆盖矩阵与「拆分出口」（草案曾建议简化 G4 校验，按 B5 改为保留） |
| K10 | G5 结构检查：审查者、未参与实现、关键问题 0、审查状态绑定、CR 轮次上限 | `ck_g5` | 全部真实缺陷由独立审查发现；B2 写评分离 |
| K11 | G6 ②③ 当次人工决定 | `ck_g6` | B2 红卡必须人确认 |
| K12 | 红线文件与漂移阻断、TTY 确认基线 | `redline_state`、`baseline` | B3 阈值放独立红线配置，改动停下等人确认；基线须交互终端，Agent 的非交互 shell 无法自行重置 |
| K13 | 任务池全部子命令 | `ai-task-pool.sh` | 维护者明确要求（T-000001、T-000002）；不再扩展 |
| K14 | 安装与升级 | `bin/ai-harness` | 下游分发唯一路径 |
| K15 | 规则入口、阶段指南、`MEMORY.md`、模块活文档 | `AGENTS.md`、`.agents/skills/`、`docs/architecture/` | B5 规则、模块文档、记忆三分；按阶段加载 |
| K16 | 体积体检 | `ai-check-bloat.sh` | B1 规则膨胀稀释注意力 |

### 3.2 删除

| # | 功能 | 位置 | 依据 | 替代 |
| :-- | :-- | :-- | :-- | :-- |
| D1 | G2 含糊词表 | `ck_g2` 词表 awk | 只有误报；B1、B3 含糊词属于理解判断，由 AI 审查扫出 | 写进设计审查与 `code-review.md` 清单 |
| D2 | G6 证据关键词扫描、零计数与引号豁免 | `G6_SCAN_AWK`、`G6_PASS_RE`、`g6_scan` | 只有误报；B3「输出是 X 则通过」 | G6 冒烟、AC 汇总、逐条 AC 只认行首结构化结论「通过」，证据文本不扫描（即 ADR-0001 决定 2A） |
| D3 | G1 可行性 7 维加权评分表及算术校验 | `ck_g1`、模板 §6 | B4 的评分由平台独立评估 AI 打分；本仓库是同一 Agent 自评，22 个 Spec 全部通过，属自我确认 | 象限与分级依据（K6） |
| D4 | 条件委托（预授权）与 G3 哈希快照 | `delegation_fields`、`validate_delegation`、`hash_text` 相关 | 使用 0 次；引出 T-000011 升级兼容问题；B2 红卡必须当次确认 | ②③ 一律当次人工决定（K11） |
| D5 | 知识卡系统 | `ai-knowledge.sh`、G4「知识检索 / 注入知识」校验、`knowledge-distill.md`、`.knowledge/`、`KNOWLEDGE_TTL_DAYS` | 全仓 1 张卡；B5 三层模型中没有这一层；B4 指出过期知识的风险 | 经验写 `MEMORY.md`，稳定后按 `gc-memory.md` 晋升到模块活文档 |
| D6 | `pass --by human` 人工身份标记 | `cmd_pass` | 使用 0 次；不提供认证（B2 软约束） | 人的决定记录在 `acceptance.md` |

## 4. 迁移

一个 Spec 实施、一次下游升级。

| 阶段 | 内容 | 入口任务 | 依赖 | 下游升级影响 | 回滚 |

| R1 | D1~D6：删代码、模板字段、指南段落与自检用例；`code-review.md` 增加含糊词检查项 | T-000032（待办，已指定为下一项） | 无 | 需 upgrade；在途 Spec 须先归档，或按新格式重写 `acceptance.md`（去掉委托字段、AC 行首写「通过」） | `git revert`，下游重新 upgrade |
