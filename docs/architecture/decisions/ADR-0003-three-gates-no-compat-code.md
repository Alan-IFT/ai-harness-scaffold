# ADR-0003：三道门，不写 CLI 与兼容代码，持续做减法

- 状态：已决定
- 日期：2026-10-25
- 替代：ADR-0001、ADR-0002（已删除，见 Git 历史）
- 来源：维护者原话「是不是想太多了，我想要的是非宿主绑定的……现在的整个脚手架是否考虑太多？是否需要简化，以符合初衷和在博客上学习到的点」「不要管兼容的问题，少就是多……写个说明，让对应项目的AI照着统一说明操作就是」「没必要做cli……cli命令太死板了，遇到特殊情况就无法处理了，不如skill智能」「只要是会导致整个脚手架变得臃肿、累赘的，都应该删除」；三门制由维护者在对话中选定。

## 1. 依据

参考博客（维护者的 `AI辅助开发管理博客`）提炼的原则：
- **B1**：能用工具确定性检查的交给工具，需要理解和判断的交给 AI；规则越多注意力越稀释。
- **B2**：门禁看骗不过的客观信号（命令跑过、状态一致），不看文件里有没有某个字段；循环有成本上限，触顶交人。
- **B3**：阈值放在独立红线配置，改动要人确认；进度存文件，用命令推进。
- **B6**：流程是手段，多余的环节就拆掉。

本仓库证据：G1~G7 时期机制代码约 3500 行，正式验证 470 秒；真实缺陷都由独立审查发现，格式检查只留下误报；一次目录重命名走完七道门用了约 7 小时。

## 2. 决定

1. **三道门**：g1 计划（原话、需人决定是 / 否、验收标准、待确认清零、方案与任务）→ g2 验证（任务全勾、正式验证 PASS 且对应当前代码）→ g3 审查（独立上下文、关键问题 0、轮次上限、审的是当前验证状态；需人决定时有人的当次通过）→ 归档。
2. **保留的核心**：任务池、Spec 与 WIP 接力、`ai-verify` 与状态指纹、独立审查与轮次上限、红线基线、`ai-resume` 的 owner / review。
3. **不写 CLI 与兼容代码**：接入写在 `skill/SKILL.md`，升级与降级写在 `template/.agents/skills/upgrade.md`，由 AI 判断执行。只支持 Windows（Git Bash）。
4. **持续做减法**：只要会让脚手架臃肿、累赘就删除，追溯交给 Git。已删除的包括：象限分级、覆盖矩阵与任务追溯、`design.md` / `acceptance.md`、`bin/ai-harness` 全部命令、manifest 与布局迁移、无脚本读取的红线键、任务优先级、`--quick`、工具链自动探测、worker 角色、手动 `start`、`--force` 与审计流水、`metrics` 子命令、示例 / 路线图 / CI 文档、宿主专属文件（`.cursorrules`、`.cursorignore`、`.claudeignore`）、`gc-memory` 与老项目接入指南（并入 `AGENTS.md` 与 `skill/SKILL.md`）。

## 3. 回滚

`git revert` 对应提交。已归档 Spec 的 `.gates` 保留旧门记录，不影响内容。
