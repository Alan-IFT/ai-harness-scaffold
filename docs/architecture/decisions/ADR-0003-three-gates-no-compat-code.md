# ADR-0003：三道门，不写兼容代码

- 状态：已决定
- 日期：2026-10-25
- 替代：ADR-0002 §3.1 的 K6~K11（G1~G7 七道门及其结构检查）与 R2 的下游迁移方式
- 来源：维护者原话「是不是想太多了，我想要的是非宿主绑定的……现在的整个脚手架是否考虑太多？是否需要简化，以符合初衷和在博客上学习到的点」「不要管兼容的问题，少就是多，脚手架的升级和降级……写个说明，让对应项目的AI照着统一说明操作就是」「迁移或升级都不要写代码，只写个说明就行」；精简方案由维护者在对话中选定「三门制」。

## 1. 证据

| 信号 | 数据 |
| :-- | :-- |
| 机制代码 | 约 3500 行，其中 `ai-gate.sh` 637 行、自检 884 行、`bin/ai-harness` 754 行 |
| 正式验证 | 470 秒，`VERIFY_MAX_SECONDS` 为 120 秒 |
| 流程成本 | feat-t-000033（一次目录重命名）走完 G1~G7 与两轮独立审查，G3 → G4 约 7 小时 |
| 真实缺陷来源 | ADR-0002 §2：都由独立设计审查或 G5 发现，格式检查只留下误报 |
| 兼容代码 | R2 写了约 270 行下游迁移与旧布局守卫；`upgrade` 与 manifest 基线约 360 行，配 190 行回归 |

对照 ADR-0002 的 B1（能用工具检查的交给工具，规则越多越稀释）、B2（看骗不过的客观信号）、B6（多余的环节就拆掉）。

## 2. 决定

1. **三道门**：g1 计划（原话、需人决定是 / 否、验收标准、待确认清零、方案与任务）→ g2 验证（任务全勾、正式验证 PASS 且对应当前代码）→ g3 审查（独立上下文、关键问题 0、轮次上限、审的是当前验证状态；需人决定时有人的当次通过）。三道门过后归档。
2. **删除**：象限 ①~④ 与分级依据、四项必答、EARS 与原文锚点、覆盖矩阵与任务追溯、模块关联与检索依据的结构检查、`design.md` 与 `acceptance.md`。方案并入 `tasks.md`，人的决定并入 `review.md`。
3. **保留**：任务池、Spec 与 WIP 接力、`ai-verify.sh` 与状态指纹、独立审查与 CR 轮次上限、红线基线、`ai-resume.sh` 三种角色、`--force` 审计与 `reset`。
4. **不写兼容代码**：删除 `upgrade` 命令、manifest 基线、下游布局迁移与旧布局守卫。升级、降级与跨版本变化写在 `template/.agents/skills/retrofit-legacy.md`，由项目 AI 比对目标版本 `template/` 手动完成。只支持 Windows（Git Bash），不为其他系统做适配。
