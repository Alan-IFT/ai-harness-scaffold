# 接入技能

- **范围**：`skill/SKILL.md`（新项目与老项目接入）、`template/.agents/skills/upgrade.md`（升级与降级）。
- **为什么不做 CLI**：曾有约 750 行 `bin/ai-harness`。命令行规则死板，老项目的特殊情况处理不了，最后还是要 AI 合并冲突、选验证命令和试点模块（ADR-0003）。
- **为什么只装 Git 跟踪的文件**：`template/` 里可能有工具留下的临时文件，不能被带进目标项目。
- **为什么记提交号不记版本号**：版本号要人记得改，模板改了多次仍停在 2.0.0，升级时找不到基线；提交号在接入时自动确定，`git show` 就能取回当时的模板。
- **为什么默认取最新 tag**：公开后 `main` 上可能有未发布的改动。tag 只决定默认取哪个版本，`.ai-harness/version` 仍记提交号。拉取 tag 失败时停下问人，不静默回退 HEAD，否则会装到未发布的版本。
- **为什么不切换脚手架工作区**：用 `git ls-tree` 与 `git show` 按版本读模板，不动维护者正在开发的工作区，也不会把未提交的改动装进目标项目。
- **为什么声明放 `.ai-harness/LICENSE.md`**：放接入项目根目录会把项目误标成 MIT，也可能和项目自己的 `LICENSE` 冲突。
- **为什么验证命令要能证明行为**：g2 是唯一真正执行项目代码的关卡；会跑关联测试的自动探测在 d8109ac 删掉，去掉 CLI 时（7b314fd）选命令又写成了「能对单个文件跑的检查」，示例只剩 lint 与类型检查。已接入项目可能还留着这样的命令，所以升级时也要复议；`verify.conf` 属项目状态，只提示，由人决定。
- **为什么读所选版本的升级说明**：克隆很久没更新时工作区里的说明比目标版本旧，照着做可能漏掉新增的机制文件。
- **验证**：改 `skill/SKILL.md` 后按它在临时目录实际接入一次新项目，确认自检通过。
