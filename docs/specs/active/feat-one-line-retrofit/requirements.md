# 需求与验收规范：feat-one-line-retrofit

- 创建时间：2026-10-20
- 状态：Approved
- 需求来源：用户希望在 Claude Code 或 Codex 中用一句自然语言启动老项目接入
- 原始问题 / 原话：「为什么不做成skill或轻量工具呢？这样我直接给AI简单说一句就行」
- 需求分级（象限）：③ 人机协同·复杂度侧；跨宿主技能发现、已有文件保护与老项目 Git 状态有关
- 分级依据：全局入口若复制第二份流程会漂移；安装器不能覆盖用户已有技能或在 worktree/单仓子目录创建嵌套仓库

## 0. 必须明确（四项）
- 做什么：把已有共享技能与 retrofit CLI 接成 Claude Code、Codex 都可发现的一句话入口
- 为谁做：维护多个老项目、会在不同 IDE 和 Agent 之间切换的用户
- 关键业务规则：一份流程正文留在本仓库；宿主技能只保存发现元数据和源路径；老项目改造仍遵守只读预演、冲突隔离和渐进试点
- 验收标准：一次安装后可在两宿主凭自然语言或显式技能名定位共享流程；安装可重复且不覆盖无关技能；CLI 对已有 Git worktree 和单仓子目录不新建嵌套仓库

## 1. 背景与目标
已有 `skill/SKILL.md` 和 `bin/ai-harness retrofit`，但 `install-skill` 默认只装入 DSH，跨宿主发现需要用户手写长提示。现有 `is_git_repo` 仅检查 `.git` 目录，对 `.git` 文件的 worktree 或已有仓库子目录会误判。

- Non-Goals：不建立宿主专有流程副本；不改任何老项目业务代码；不把用户的项目路径写死到技能里；不自动安装到尚未指定的其他机器。

## 2. 结构化需求
- REQ-01：WHEN 用户安装 Codex 或 Claude 技能，THE CLI SHALL 在对应用户技能目录生成指向本仓库共享技能的薄入口，支持显式 `--dest` 测试路径。
- REQ-02：WHEN 用户说「把这个老项目接入脚手架」，THE SKILL SHALL 定位目标项目、读取共享老项目指南并调用现有 retrofit CLI；不要求用户复制多段命令。
- REQ-03：WHEN CLI 在已有 Git 仓库、worktree 或仓库子目录执行 retrofit，THE CLI SHALL 不创建嵌套仓库。
- ERR-01：IF 目标技能目录已有非本安装器管理的内容，THEN 安装 SHALL 拒绝覆盖且不改动原文件。
- ERR-02：IF 同一宿主及来源重复安装，THEN 结果 SHALL 幂等；不同来源不得静默改写指针。

## 3. 验收标准
| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 一句话发现 | Codex、Claude 入口均有合法 SKILL.md，指向同一共享流程与 CLI；自然语言示例简短 | 两份流程正文或需粘贴长提示 | 临时安装样本、技能校验、README |
| AC-02 | 安装安全 | 同源重装幂等，非管理目录与异源入口拒绝覆盖 | 覆盖已有用户技能 | 正反例测试 |
| AC-03 | 老仓库安全 | worktree/父仓库子目录不被 `git init` 成嵌套仓库 | 产生嵌套 `.git` | 临时 Git 样本 |
| AC-04 | 原流程兼容 | 旧 DSH 安装与 retrofit CLI 可用；正式自检通过 | 破坏旧调用或门禁 | CLI 冒烟、正式验证 |

## 4. 待确认问题
- [x] Q1：复制完整技能到各宿主？→ 不复制流程正文；各宿主仅保留薄入口和源路径。
- [x] Q2：是否自动修改所有老项目？→ 由用户一句话指定目标项目；实际接入仍由 Agent 逐项目执行。

## 5. 非功能性约束
- 性能：技能加载只读薄入口；不在每次对话复制模板。
- 安全与权限：拒绝覆盖陌生技能；安装到用户目录时遵守当前机器文件权限；不自动 push。
- 兼容与迁移：保留 `install-skill` 原 DSH 默认语义；Codex/Claude 需显式 `--host`。
