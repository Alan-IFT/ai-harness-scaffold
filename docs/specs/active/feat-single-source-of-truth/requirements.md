# 需求与验收规范 (Requirements): feat-single-source-of-truth

- **创建时间**: 2026-10-20
- **状态**: Approved（依据 R-002 与本会话授权）
- **需求来源**: 维护者；`docs/INTAKE.md` R-002
- 原始问题 / 原话：「最好是一个事实只在一个地方存在，不要多个地方存在相同事实，导致一个地方改了，其他地方没改，形成信息错乱；脚手架的设计也是如此」；「前面的两个 spec 后开始做」。
- 需求分级（象限）：③ 人机协同·复杂度侧；涉及脚本、配置、指南、模板与本仓库自用边界。
- 分级依据：阈值散落在配置、脚本默认值和说明文档；维护者 已决定「一个事实只在一个地方」，Agent 负责具体拆分和验证。

## 0. 必须明确
- 做什么：将配置值、可执行机制、项目状态与说明分别收敛到明确的唯一所有者，并防止漂移。
- 为谁做：在 Claude Code、Codex 等工具间接力的开发者，以及把脚手架装进新旧项目的维护者。
- 关键业务规则：`template/` 保存分发机制；每个项目自己的 `harness/redlines.conf` 保存该项目阈值；根目录脚本只转发；说明文档引用配置键而不复制可变值；缺失或无效的必要配置显式报错。
- 验收标准：根目录自用与模板安装样本都通过自检；改配置后按新值工作；错误配置不会退回隐含默认值；重复事实审计无未解释的副本。

## 1. 业务背景与目标
当前 `harness/redlines.conf` 被称为阈值来源，部分脚本却在配置缺失或错误时回退到内置数字，指南和模板还复述这些数字。切换宿主或用于老项目时，副本可能分叉。目标是使修改入口清晰、错误显性化，项目文档继续可交接。

- **Non-Goals（本次明确不做）**：
  - 不把不同项目的阈值强制共用一个文件；模板配置是新项目初始样本，目标项目与本仓库自用配置各自独立。
  - 不引入数据库、外部记忆服务、IDE 专属状态或新审批平台。
  - 不改门禁象限和阶段语义，不调整阈值数值。

## 2. 结构化需求
### 2.1 正常流
- **REQ-01**: WHEN 用户修改项目 `harness/redlines.conf` 的受支持阈值并完成现有基线流程，THE SYSTEM SHALL 从该文件读取实际阈值，文档只引用该键。
- **REQ-02**: WHEN 本仓库通过根目录 `scripts/` 运行命令，THE SYSTEM SHALL 执行 `template/scripts/` 中同一机制；目标项目安装后 SHALL 拥有可独立运行的机制副本。
- **REQ-03**: WHEN Agent 交接任务或归档 Spec，THE SYSTEM SHALL 以项目内 Spec、架构文档和 Git 为状态记录，需求入口链接应指向实际位置。

### 2.2 异常与边界流
- **ERR-01**: IF 必要配置缺失或数值无效，THEN 依赖它的命令 SHALL 清楚失败，不静默采用另一份默认值。
- **ERR-02**: IF 同一索引内容提交后没有其他代码变化，THEN 验证摘要 SHALL 继续有效，文案不应要求无意义的重验。
- **ERR-03**: IF 根目录与目标项目阈值不同，THEN 两者 SHALL 各自读取自己的配置。

## 3. 验收标准
| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 阈值单源 | 每项目的受支持阈值仅由其 `harness/redlines.conf` 提供；脚本无回退数字 | 缺失或错误配置仍按硬编码值继续 | 修改阈值正例、缺失与非法值反例 |
| AC-02 | 文档单源 | 入口、指南与 Spec 模板引用配置键，不复述同一阈值 | 改配置后指南留旧数字 | 有界 `rg` 审计与所有权表 |
| AC-03 | 机制单源 | 根脚本薄转发，模板脚本可独立安装 | 根脚本有第二套校验或安装缺依赖 | 薄转发审计、根目录和安装样本自检 |
| AC-04 | 状态一致 | `docs/INTAKE.md` 链接有效，验证摘要说明与状态指纹一致 | 链接失效或无改动提交被描述为过期 | 链接检查、暂存到提交指纹测试 |
| AC-05 | 回归保护 | 门禁、验证、体积、知识命令通过，配置异常有自动断言 | 原有断言回归或错误配置被吞掉 | `harness-selftest.sh`、`ai-verify.sh`、`git diff --check` |

## 5. 非功能性约束
- **性能**：只读本地配置，不增加网络或全仓扫描。
- **安全与权限**：不增加执行外部文本的入口；保留基线与 Git 审计语义。
- **兼容与迁移**：旧项目若缺必需键要获得明确诊断；完整配置的项目行为保持一致。
