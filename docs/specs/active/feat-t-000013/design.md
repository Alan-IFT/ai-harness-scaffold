## 1. 架构变更与数据流

新增 `g6_scan()`：把一行证据文本交给 awk，先用 index/substr 成对剥离「」『』与反引号内容（与 ck_g2 的 strip 写法一致），再用 match 循环只替换命中的零计数段、前后字符原样保留（不能用 gsub 连带边界字符，否则「不通过0 项失败」会被吞成「不通」）：`失败 *:? *0( *(项|个|条|次))?` 与 `0 *(项|个|条|次)? *失败`。判断边界前先跳过相邻空格：零计数之后只允许行尾、`;)` 或「，。；、）」，其他文字一律不豁免（挡住「失败 0 5 项」「不通失败 0 过」）；第一式另要求「失败」前不是数字（挡住「1 失败 0 项」，代价是「通过 12 失败 0」须写成「通过 12，失败 0」）；第二式另要求 0 前不是数字（含全角）、小数点、逗号、冒号、斜杠、正负号、字母、`_`、`#`、「、」或「第」（挡住「共 1 0 项失败」「第 0 次失败」「v0」「-0」）。nv 已把「：」归一为「:」，正则不再含全角冒号分支。字符类只含 ASCII，多字节用字面量（K-0001）。`g6_scan` 用 `$(...)` 捕获 awk，失败或对非空输入输出为空时回退原文（不放宽）。ck_g6 三处关键词 `case` 改对 scan 结果判断；空值与 `<` 占位仍用原文。冒烟与 AC 摘要的正向判定改对只剥引号的文本（mode=strip，awk 失败回退为空，不放宽）匹配 `通过|PASS|成功|(^|[^0-9.,/])0 *(项|个|条|次)? *失败`，堵住「10 失败」借子串命中。

## 5. 对抗自审

1. 最可能错在哪：零计数正则把非零数字误判为零；已用「10 项失败」「失败 05」「失败 0.5 项」原型验证不豁免。
2. 关键前提：「豁免后矛盾记录仍会被拦」——矛盾记录一般不带零计数；但写成「失败 0 项，但功能失败」时，第二个「失败」不带数量，仍被拦。
3. 边界：引号可被滥用把整句包起来绕过；「步骤 0 失败」这类「名词+0」编号写法有歧义，按零计数放行。两者都靠 G5 审查发现，模板写明只引用原文、编号用「#」或「第」。
4. 能否更简单：只豁免引号更简单，但「失败 0 项」这类计数仍需改写，不满足维护者选的方案。
5. 回滚：`git revert`。

- 独立设计审查：审查者：独立 subagent（未参与设计，只读）；结论：首轮「需修改」，2 项关键问题——gsub 连带吞掉边界字符可绕过（「不通过0 项失败」→「不通」，gawk / mawk 实测）、冒烟正向判定「0 失败」被「10 失败」子串命中——已改为 match 循环只替换命中段并收紧前后边界，正向判定改用只剥引号文本并要求 0 前非数字；采纳 0,5 / 0/3 收紧、去掉多余全角冒号分支、写明 `$(...)` 回退等建议。实现方复测时另发现全角数字「１0 失败」被放行，已加全角数字判断。第 2 轮「需修改（小改）」：序数「第 0 次失败」与数字间夹空格「失败 0 5 项」「共 1 0 项失败」可绕过——已改为判断边界前跳过空格、把「第」与正负号、字母计入非零上下文、零计数后只允许句读；「v0」「-0」按非零处理。第 3 轮「通过」：41 例（含审查补测的「失败 0；另 2 项失败」「失败 0 项|但不通过」及采纳建议补入的「#0」「case_0」）在 gawk、mawk、onetrue-awk 的 C 与 C.UTF-8 下均符合期望；吞字、子串命中、序数、空格夹数字等绕过已封堵；「步骤 0」类编号写法留作 G5 关注点。
