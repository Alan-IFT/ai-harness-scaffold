## 0. 必须明确（四项，缺一项不得进入设计）

- 做什么：G6 对冒烟证据、AC 核验摘要、逐条 AC 行做关键词检查前，先剥离「」『』与反引号内的原文，并去掉数量为零的失败写法。
- 为谁做：填写 `acceptance.md` 的 Agent 与做 G6 判断的维护者。
- 关键业务规则：「失败」「未执行」「未检查」「不通过」在剥离后仍出现就拒绝；只有数量恰为 0 的「失败」写法被豁免；非零数量不豁免。
- 验收标准：「失败 0 项」「0 项失败」「失败：0」与引号内原文可通过；「通过，但测试失败」「10 项失败」仍被拒；两种 locale 结论一致。

## 1. 业务背景与目标 (Context & Goal)
- **背景**：feat-t-000006 的 G6 因 AC 行写「失败 0 项」「基线 21 项失败」被拒，只能改写措辞。现有冒烟正向判定本已接受「0 失败」，却总被前面的关键词检查先拦下，说明原意允许零数量写法。
- **完成后的行动与效果**：Agent 可以如实写测试计数与引用基线，不必为过门禁改写事实；矛盾记录仍被拦下。
- **Non-Goals（本次明确不做）**：
  - 不改为只看行首判定的结构化方案（维护者否决方案 B）；不扩大关键词表；英文 `0 failed` 本就不含中文关键词，无需处理。

## 2. 结构化需求 (EARS Acceptance Criteria)

### 2.1 正常流 (Happy Paths)
- **REQ-01**: WHEN 证据写成数量为 0 的失败计数（「失败 0 项」「失败：0」「0 项失败」「0 失败」），G6 SHALL 不因这几个字拒绝。
- **REQ-02**: WHEN 关键词只出现在「」『』或反引号内，G6 SHALL 不因此拒绝。

### 2.2 异常与边界流 (Edge Cases & Error Handling)
- **ERR-01**: IF 剥离引号与零计数后仍含「失败」「未执行」「未检查」「不通过」，THEN G6 SHALL 拒绝。
- **ERR-02**: IF 失败数量非零（如「10 项失败」「失败 3 项」「失败 05」），THEN G6 SHALL 拒绝。
- **ERR-03**: IF 文本预处理的 awk 执行出错，THEN G6 SHALL 按原文判断（不放宽）。
