## 2. 实现顺序、垂直切片与检查点

1. 步骤 1：写 ADR 草案（四问题、迁移表、分诊草案、空决定表），在 `00-INDEX.md` 登记。
2. 步骤 2：独立 subagent 只读审查 ADR 草案的证据准确性、方案完整性与推荐理由；按意见修订。
3. 步骤 3：向维护者逐项呈现四个问题，记录决定；未决定的标待定并从迁移表中去掉依赖它的阶段。
4. 步骤 4：按决定定稿分诊表，逐条 `ai-task-pool.sh update` 写入 T-000015~T-000026 与 T-000028 并按映射手工改写队列状态；为缺入口的迁移阶段用 `add`（不触发自动启动）收录任务，回填进 ADR 迁移表；`prefer` 指定第一个阶段入口。

- **检查点**：
  - 检查点 1（步骤 4 后）：`git diff --stat <G3 基准>..HEAD` 不含 `template/`、`bin/`、`scripts/`；13 个任务文件（含 T-000028）各有一条 2026-10-23 的分诊补充，`ai-task-pool.sh list` 的状态与结论映射一致，`docs/task-pool/NEXT` 为第一个阶段入口且它是唯一的未关联待办。
- 边界样本：维护者只决定部分问题（如问题 3 待定）→ 迁移表去掉阶段 1 与阶段 5，T-000015、T-000018 改为暂缓并注明「待问题 3 决定」，第一个阶段改为阶段 2；维护者否决推荐方案（如问题 2 选 2C）→ T-000016、T-000017、T-000022~T-000024 改为「暂缓（冻结）」而非作废；选 2B 而非 2A → 阶段 2 改为降级警告且不删用例，T-000017 保留；四个问题全部待定 → 本 Spec 判为不通过，不改任何队列状态；任务原件出现跨阶段依赖（如 T-000021 同时涉及字段解析与流程路径）→ 合并到最早相关阶段；`next` 若仍指向旧任务（NEXT 文件残留）→ 重新 `prefer` 第一个阶段入口。

1. 最可能错在哪：推荐方案被我的倾向带偏（例如低估 1B 迁移成本或 2A 放弃自动发现的代价）；由独立审查核对证据和代价，并由维护者逐项决定。
2. 关键前提：「边角任务来自正则判断自然语言」——T-000006~T-000013、T-000022~T-000024 的原件可核对。
3. 边界：维护者可能只决定部分问题；迁移表与分诊按待定处理，不预排依赖阶段。
