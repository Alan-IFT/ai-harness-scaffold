# 需求与验收规范：feat-task-pool

- 创建时间：2026-10-21
- 状态：Approved
- 需求来源：用户本次会话
- 原始问题 / 原话：「新增任务池，我往里面扔任务，然后我在一个AI完成一个任务后，再开新会话，让AI接着完成下一个任务……方便的及时更新需求」
- 需求分级（象限）：③；涉及跨会话持久状态与 Spec 流程衔接。
- 分级依据：状态重复会导致错领任务；稳定 ID 与派生状态可控制复杂度。

## 0. 必须明确
- 做什么：提供可追加、可更新、可排序的项目任务池与下一项命令。
- 为谁做：在多个 AI 会话间继续同一项目的维护者和主 Agent。
- 关键业务规则：未结束 Spec 优先续做；否则按优先级和 ID 领取待办；原话和补充留在同一个任务文件，任务只关联稳定 Spec ID。
- 验收标准：新会话能发现下一步；记录任务和更新不覆盖原文；归档后自动跳到下一任务。

## 1. 背景与范围
现有 docs/INTAKE.md 是处理决定的历史入口，缺少可执行队列。新增 docs/task-pool/ 作为新需求的唯一记录；既有 INTAKE 历史保留。

## 2. 结构化需求
- **REQ-01**：WHEN 提出想法，THE SYSTEM SHALL 创建稳定任务 ID、保留原话及优先级。
- **REQ-02**：WHEN 需求变化，THE SYSTEM SHALL 追加带日期的补充，不改写原始需求。
- **REQ-03**：WHEN 新会话查询下一项，THE SYSTEM SHALL 优先返回活跃 Spec；否则返回优先级最高且 ID 最早的待办任务。
- **REQ-04**：WHEN 开始待办任务，THE SYSTEM SHALL 创建 Spec 并只记录稳定 Spec ID；进行中/完成状态由 Spec 位置派生。
- **ERR-01**：IF ID 或优先级无效，THEN THE SYSTEM SHALL 报错且不覆盖已有任务。
- **ERR-02**：IF 任务已有关联或目标 Spec ID 已占用，THEN THE SYSTEM SHALL 拒绝且不改写任务。

## 3. 验收标准
| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 收集与更新 | add 产生独立文件，update 追加 | 原话丢失或覆盖 | 自检检查两次更新后原话仍在 |
| AC-02 | 下一项 | 活跃 Spec 优先；待办按 P0/P1/P2、ID 排序 | 选到暂缓或归档任务 | 自检覆盖两种路由 |
