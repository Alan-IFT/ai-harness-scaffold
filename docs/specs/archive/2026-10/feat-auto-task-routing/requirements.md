# 需求与验收规范：feat-auto-task-routing

- 创建时间：2026-10-22
- 状态：Approved
- 需求来源：`docs/task-pool/T-000002.md`
- 原始问题 / 原话：「我给AI说需求，AI自动研判当前是否有正在做的需求，若有则添加到任务池，若无且任务池为空则开始做当前需求；任务池默认根据先后顺序完成，人工可要求先做哪个需求」
- 需求分级（象限）：③；跨会话自动路由涉及持久顺序、覆盖与现有 Spec 流程。
- 分级依据：错误路由可能跳过旧任务或并发创建 Spec；单脚本状态检查、队列文件和回归测试可限制影响。

## 0. 必须明确
- 做什么：AI 收到自然语言新需求时自动记录，并按当前 Spec 与任务池状态决定续做或启动；默认按收录先后完成，维护者可指定下一项。
- 为谁做：使用脚手架跨会话开发的维护者与主 Agent。
- 关键业务规则：活跃 Spec 优先续做；无活跃 Spec 时待办按 T-ID 升序；指定下一项是一次性持久覆盖；补充既有需求需更新同一任务及已开始的 Spec。
- 验收标准：新需求无需维护者运行命令；空池自动启动当前需求；已有待办时收录新需求并启动最早待办；指定下一项跨会话有效且使用后清除。

## 1. 背景与范围
现有任务池要求维护者或 AI 手动执行 add、next、start，且旧优先级主导顺序。改成自然语言入口和机械路由，保留项目内持久记录。

## 2. 结构化需求
- **REQ-01**：WHEN 维护者提出独立新需求，THE SYSTEM SHALL 保存原话；有活跃 Spec 时只入队并继续原 Spec。
- **REQ-02**：WHEN 无活跃 Spec，THE SYSTEM SHALL 在收录新需求后启动按顺序应做的待办；空池时该待办即当前需求。
- **REQ-03**：WHEN 未指定下一项，THE SYSTEM SHALL 按任务 ID 升序选待办，优先级字段不改变顺序。
- **REQ-04**：WHEN 维护者指定待办任务先做，THE SYSTEM SHALL 持久记录一次性选择；活跃 Spec 结束后优先该任务，成功启动后清除选择。
- **REQ-05**：WHEN 维护者补充或修改已记录需求，THE SYSTEM SHALL 追加同一任务；已开始任务还须同步更新 Spec 并回退受影响门。
- **ERR-01**：IF 指定任务不存在、暂缓、取消或已有 Spec， THEN THE SYSTEM SHALL 拒绝且保留旧选择。
- **ERR-02**：IF 自动启动因模板、并发或 ID 冲突失败， THEN THE SYSTEM SHALL 保留已收录任务供恢复，不创建第二个活跃 Spec。

| 对应需求 ID | 来源 | 原文关键短句 | 设计时必须保留的语义 |
| :-- | :-- | :-- | :-- |

| REQ-02 | 本次用户消息 | 「若无且任务池为空则开始做当前需求」 | 空池立即开始；非空池遵循既有队列 |

## 3. 验收标准
| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 自动收录与启动 | 空池 intake 建任务及 Spec；活跃 Spec 下只入队 | 需要人手工运行三条命令或出现双活跃 Spec | 自检覆盖空池、活跃、非空池 |
| AC-02 | 默认顺序 | P0 后录入仍排在旧 P2 后 | 优先级改变 next 结果 | 自检断言 ID 顺序 |
| AC-03 | 人工指定 | 指定目标跨活跃会话保留，启动后清除 | 指向非法任务或永久置顶 | 自检覆盖选择、拒绝、消费 |
| AC-04 | 指南与失败恢复 | AI 规则说明独立需求/补充的路由和异常恢复 | 人仍需记忆 CLI 或重试产生重复任务 | AGENTS、技能、README 对照与自检 |

## 4. 待确认问题
产品规则已由维护者本次消息明确；实现取舍按本次会话维护者答复留痕。无其他阻塞问题。

## 5. 非功能约束
保留旧任务文件与 `--priority` 读写兼容，但该字段仅供展示。`next` 和 `list` 只读；不引入服务或外部依赖。失败后任务原件保留，避免丢需求。
