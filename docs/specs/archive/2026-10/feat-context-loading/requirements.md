# 需求与验收规范：feat-context-loading

- 创建时间：2026-10-20
- 状态：已按用户决定更新并通过 G1~G6，待归档
- 需求来源：用户在本会话询问 subagent 间重复加载是否拖慢实现，随后要求创建本 Spec。
- 原始问题 / 原话：「现在这套脚手架，会导致同一个信息，在不同subagent之间无意义的复制吗？进而导致AI实现一个需求的时间被严重拉长吗？」；「那就开一个spec：优化重复加载风险」。
- 后续决定 / 原话：「我觉得A、B都应该改」；「若有更好的设计方案，`ai-resume.sh [feat]` 用法不再兼容 ，因为好的设计好过不断的修修补补，该重构时就要重构」。
- 需求分级（象限）：③ 人机协同·复杂度侧；涉及跨角色接手、独立审查和模板脚本的兼容设计。
- 分级依据：错误裁剪上下文会漏掉真实需求或使 G5 审查依赖实现者自述；耗时改善需要先建立可比基线。

## 0. 必须明确（四项）

- 做什么：减少同一需求中多个 Agent 无用的重复加载，并用可复核的代理指标判断优化是否有效。
- 为谁做：使用本脚手架在 Codex、Claude Code 或其他工具中接力、并行实现与独立审查的维护者和 Agent。
- 关键业务规则：按角色与任务边界加载；保留 G5 独立读取需求、代码和验证证据；没有可靠的宿主 token 数据时不把输出字节数当成实际 token 或完成时间。
- 验收标准：角色化接手样本减少无关重复输出，旧调用明确提示迁移，G5 必需证据可达，报告同时记录加载代理指标与可得的实际耗时。

## 1. 背景与目标

现有 `AGENTS.md` 要求分层读取，但每个新会话都接手并显式读取通用规则；`ai-resume.sh` 默认输出上下文体检、门状态、活跃 Spec、Git 状态和知识检查。G5 另需独立上下文回读原始证据。这些读取里有必要重复，也可能有与某个 worker 任务无关的部分。现有 `docs/metrics.md` 没有按角色记录重复加载量，不能据此断言它已严重拉长需求耗时。

- 目标：给主 Agent、限定文件的 worker、独立审查者明确的最小接手输入；减少非必要的重复输出和全文转贴。
- Non-Goals：取消 G5、跳过门禁、自动读取宿主对话或私有 token 账单、以字节代理指标承诺真实耗时必然下降。

## 2. 结构化需求

- REQ-01：WHEN 新 Agent 接手限定任务，THE HARNESS SHALL 给出与角色及任务边界匹配的读取入口，避免默认要求复制整份 Spec 或上一 Agent 对话。
- REQ-02：WHEN 独立审查者接手 G5，THE HARNESS SHALL 指向需求原文与 AC、设计映射、完整相关 diff、验证摘要及相关契约，并保持审查者不依赖实现者自述。
- REQ-03：WHEN 比较优化前后，THE HARNESS SHALL 对同一固定样本记录接手输出字节数、重复材料项数和实际读取路径；可取得宿主 token 与墙钟时间时另记来源，不可取得时写「未知」。
- REQ-04：WHEN 调用方运行旧式 `ai-resume.sh [feat]`，THE HARNESS SHALL 明确拒绝并显示新用法；本仓库和模板中所有正式调用点 SHALL 更新为角色入口。
- ERR-01：IF 角色或任务边界无效或缺失，THEN THE HARNESS SHALL 明确报错或回退安全的完整接手，不得静默省略必需证据。
- ERR-02：IF G5 输入缺少需求原文、相关 diff 或验证状态，THEN THE HARNESS SHALL 提示补读，不得把精简摘要当成审查已完成。

## 3. 验收标准

| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 限定任务接手 | worker 只收到相关路径、任务边界与必要状态，能自行读取原件 | 默认复制完整对话或所有 Spec 全文 | 固定夹具中 worker 接手输出字节数比现有默认输出至少减少 30%；记录命令与原始字节数 |
| AC-02 | 独立审查 | G5 输入清单含原始需求、AC、相关完整 diff、验证状态和契约；不含实现者自评作为事实依据 | 精简后漏证据或让实现者摘要代替原件 | 逐项清单检查与正反例自检；G5 门禁仍有效 |
| AC-03 | 可比测量 | 基线与改后使用同一仓库状态、同一角色样本与同一计数方法 | 混用不同范围，或把字节数当作 token / 时间 | 基线和改后各一份记录：输出字节、重复项、读取路径；token/墙钟有来源才填 |
| AC-04 | 迁移与失败路径 | 旧式调用明确失败并给迁移提示；正式调用点均已改为角色入口；无效角色和缺失边界明确失败 | 旧命令静默进入错误角色或仍散落在指南中 | 自检覆盖三角色、旧式调用、无效参数和缺文件样本；仓库检索 |

## 5. 非功能性约束

- 性能：新增角色接手不得执行正式验证或扫描完整历史 Spec；样本统计与接手命令耗时均需记录。
- 安全与权限：输出仅含项目内状态和路径，不复制凭证、宿主私有对话或未经授权的外部材料。
- 兼容与迁移：`ai-resume.sh [feat]` 旧命令退役，所有正式调用点迁移；跨 IDE Markdown、G5 门禁和旧 Spec 数据格式保持可用。
