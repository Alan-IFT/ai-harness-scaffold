# 需求与验收规范：feat-requirement-trace-and-knowledge-usage

- 创建时间：2026-10-20
- 状态：Approved
- 需求来源：用户阅读《给AI写了800行规则，它反而更不听话了》后的改造要求。
- 原始问题 / 原话：「那就把发现的三个可借鉴点，按照建议方案来改动」
- 需求分级（象限）：③ 人机协同·复杂度侧；跨模板、门禁、知识工具与指南。
- 分级依据：须兼容旧 Spec，且不能增加第二份可变计数事实。

## 0. 必须明确（四项）
- 做什么：补需求到设计、任务、验证的追溯；扩展独立审查输入；派生知识卡采用统计。
- 为谁做：使用脚手架的 Agent 与项目维护者。
- 关键业务规则：机器只校验映射完整性，语义由审查判断；采用次数按 Spec 派生，不手写。
- 验收标准：新模板与门禁拦缺失映射，旧 Spec 兼容；审查覆盖新增输入；统计准确列出采用和未采用卡片。

## 1. 业务背景与目标
现有 REQ/AC 到任务已有映射，但缺少设计落点与原文回读。知识索引的引用次数仍须手动维护。
- Non-Goals：不引入代码图谱、MCP、IDE 钩子或多仓协议锁定；不要求①小改动填完整矩阵。

## 2. 结构化需求
- REQ-01：WHEN ②③需求进入设计，THE HARNESS SHALL 要求每个 REQ/ERR/AC 有设计落点，语义敏感条件有原文锚点。
- REQ-02：WHEN 拆任务和开始实现，THE HARNESS SHALL 要求任务引用设计章节并回读设计与语义锚点。
- REQ-03：WHEN 独立审查，THE GUIDANCE SHALL 对照需求原文、相关知识和本次修改的 AI 协作文件。
- REQ-04：WHEN 查询知识使用，THE TOOL SHALL 从当前及归档 Spec 派生每张卡的采用 Spec 数和未采用清单。
- ERR-01：IF 老 Spec 缺少新结构，THEN THE HARNESS SHALL 保留旧门禁兼容性。
- ERR-02：IF 同一 Spec 重复引用卡片，THEN THE TOOL SHALL 只计一次。
