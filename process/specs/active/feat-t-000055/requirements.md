## 3. 待确认问题
> 需求有歧义时列出选项让人选，不替人拍板；人回答后改成 `- [x] 问题 → 结论`。没有就删掉下面这行。
- [x] Q1：界线划在哪：哪些点必须交人定？→ A（维护者 2026-11-21：「1A2A3A,先这样用用看吧，有问题我再反馈」）
  - A（推荐）按后果划线：原话和已记录的决定都没定、不同选法会让交付结果不同的点（行为、范围、数据、参数名和文件名这类对外约定、与活文档或已有决定冲突的）都交人定；纯内部写法（函数怎么拆、变量名）AI 自己定，写进方案。后果：被问的次数变多，沙箱里「按客户导出」这个需求会有 3~4 个问题；每个问题带推荐，可以回「都按推荐」。边角仍可能被 AI 自己定：对照组里它自己定了「`--version` 写在别的参数前后都生效」，做完才说。
  - B 每个需求都先复述、等人回一句确认才能过 g1，不管 AI 觉得有没有疑问。后果：AI 没列出来的假设也有机会被看见，最稳；每个需求至少多一次往返，排队的任务每个都会停下等人。没有测过。
- [x] Q2：约束力度：只写规则，还是审查和门也卡？→ A（同一句答复）
  - A（推荐）规则 + 审查复核：`template/AGENTS.md` 加这条规则，Spec 模板和 `new-spec.md` 的措辞跟着对齐；`code-review.md` 的需求检查加半句，把「原话没定的取舍没有人的答复来源」算关键问题，验收里新旧文字对照，有增量才留。后果：不改脚本；不照规则做的要到审查才拦得住。
  - B 只加规则，不动审查。后果：改动最小；有 AI 不照规则做时没有任何一处会拦（基线里 3 次审查都放过了自答自勾）。
  - C 在 A 之上，g1 再机械校验「勾掉的问题必须带人的答复来源（日期 + 原话）」。后果：最严；要改 `ai-gate.sh`、自检和模板格式；来源是 AI 自己填的、能编，和 ADR-0003「门只查骗不过的信号」有张力；加了规则后的 4 次实验里没有再出现自答自勾，没有证据说明需要它。
- [x] Q3：人不在时（排队任务、说了「我明早来看」）遇到要交人定的点怎么办？→ A（同一句答复）
  - A（推荐）停在 g1：问题写进 Spec 和回复，整个队列等人。后果：不改脚本；排在后面的清楚任务也被堵住（一次只能有一个活跃 Spec），沙箱里就是这样：前一项停下后，后一项清楚的任务没有开工。
  - B 挂起这一项，先做队列里后面的任务，最后把问题一起交给人。后果：无人值守的时间不浪费；要给任务池加一个「等答复」状态并改 `ai-task-pool.sh`，机制变复杂。
  - 两个选项都按这条理解，提问时写了「不对请指出」，维护者没有指出：人明说「你定」「按推荐」才算授权，AI 把这句话记为来源；「我明早来看」不算。
