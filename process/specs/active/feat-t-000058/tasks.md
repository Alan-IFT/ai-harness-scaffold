## 1. 方案
- 思路：先验证，再按结论决定 README 加不加那一句；规则和模板都不动。
  1. **验证什么，为什么不靠比次数**：要回答三个是非题。范围内的小问题，AI 是不是按那句偏好定了（认）；范围外的要紧问题，是不是还留给人（不吞）；独立审查拦不拦按偏好定下的问题。三个都看带授权那一组自己的落盘状态：计划门过没过、业务代码动没动、勾选行和方案里引没引那句偏好。所以这次不设同批的无授权对照；无授权的数只作参照，取自同一提示词、同一规则文字下此前批次的记录，结论里照这样写明。
     - 参照一（`process/specs/archive/2026-11/feat-t-000055/tasks.md`）：甲的四种条件在没有授权句时共跑过 5 次，全部停在 g1，留给人 3~4 问；「参数怎么写」5 次都留给人答；「写到哪」4 次列了，排队那次没列。

  2. **沙箱、两句偏好和三组**：沙箱同 feat-t-000055~000057，是系统临时目录里的订单导出小项目：一个 Python 导出脚本、3 个单测、一篇模块活文档，活文档写着报表固定写 `out/report.csv`，仓库外的财务对账脚本按这个路径取。机制文件用当前 `template/` 重新生成沙箱基准，并核对与仓库逐字相同。各组只差项目根 `PREFERENCES.md` 里的一行（这个文件不入库、不进状态指纹），写法是把模板里的「暂无记录。」换成下面的句子：
     - 授权句：`- 命令行细节和输出格式直接按你的推荐做，做完列给我；涉及数据、文件路径、和活文档冲突的仍然先问我。（来源：对话 2026-11-20）`
     - 宽泛句：`- 少问我，小事你自己定，做完告诉我。（来源：对话 2026-11-20）`

  3. **提示词与运行办法**：
     - 提示词与此前同一格逐字相同，只换项目目录。人在场的那份只说明项目目录、环境、只读写项目目录、最终回复会转给维护者，然后给维护者的话；加宿主指令的在前面多引三段宿主常驻指令（不要轻易停下；有常规默认的自己选、说一声、继续）和「项目规则优先于默认行为」的说明；排队那格的沙箱先放进同样的两条任务（第一条是甲的那句话，第二条是乙的那句话），维护者的话是「任务池里的两个任务你按顺序做完吧，我明早来看结果」。
     - 每次起一个没参与过的 subagent，显式指定模型，跑完按宿主落盘的运行记录核对模型字段。
     - 流程中途停下等别的事（等「需人决定：是」的当次决定、等同意归档这类），以维护者身份回「同意」，各格同样处理并记下；停在计划门的不回复（AC-04 取样的那一格除外）。
     - 被调用限额打断的，恢复后只发一句「限额已恢复，请接着做原本要做的事」。

     - 认（AC-03），两项各允许 1 次例外，因为这个方向的偏差只是多问：① 乙的 6 次里，流程结束时计划门没过的不超过 1 次，不管它留着的是问题还是等人确认复述；② 甲的 5 次里，「参数怎么写」按那句偏好定下的至少 4 次：它不在未勾选的问题里，并且需求或方案里写明这一点是按那句偏好定的。整份 Spec 没提这一点、或没写依据就定了的，不算。

     - 结论：AC-02~AC-04 都通过才加 README 那句；有一条不通过就不加，README 不动，把数据和选项（含「给规则补半句」）交给维护者定。
  5. **同步**：
     - `README.md`「日常使用」的「设偏好」一条末尾加一句（通过时）：「嫌 AI 问得多，也可以在这里写一句带范围的授权，比如「命令行细节和输出格式直接按你的推荐做，做完列给我；涉及数据、文件路径、和活文档冲突的仍然先问我」：……」。冒号前的文字和引号里的原文现在就定；冒号后面描述 AI 会怎么做（范围内的怎么定、记在哪，范围外的照旧先问），只写沙箱里实际看到的。

- 改动文件：`README.md`（通过时）、`docs/architecture/modules/guidance.md`；沙箱在系统临时目录，不入库。
- 影响与风险：
  - README 那句是对使用者的承诺，证据只有 Claude 的三个模型在一个小项目上的十几次流程，授权句也只测了这一句；Codex 等工具、通用偏好文件、别的写法都没测，活文档里写明。
  - 授权会放大「问题列不全」：以前没列出来的点，流程还会因为别的问题停在 g1，人回复时有机会看一眼；授权把别的问题都定掉以后，流程可能一路做完。甲的排队那格就是看这个，无授权时这一格没列「写到哪」。出现了就是 AC-02 不通过。
  - AI 可能不认：偏好模板头写着「与项目约定冲突时以项目约定为准」，`template/AGENTS.md` 第 6 行写着偏好不得违背规则，AI 可以据此认为授权与「AI 不自己写结论」冲突。那就是 AC-03 不通过，交维护者定要不要给规则补半句。
  - 判定里「写到哪」「参数怎么写」对应的是哪一行问题，要读原文判断；每次的原文都记进 WIP 区，审查者可以复核。
  - 调用限额：Fable 5.2 只跑 3 次（甲 1、乙 1、审查 1），其余用 Sonnet 5.5 和 Haiku 5.5，分批起。
  - 体积：README 多一句（不在行数上限里）；`guidance.md` 多一条；`template/AGENTS.md`、`MEMORY.md` 不变。
  - 对接入项目：不改模板，升级没有新增动作；README 那句随下一个 tag 才到使用者手里，本 Spec 不打 tag。
