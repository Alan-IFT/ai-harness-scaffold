## 关键问题
1. `template/scripts/ai-verify.sh:20-25`：验证锁无法创建时会永远等待，而且提示是错的。
   - 复现：在临时仓库里 `mkdir .git/ai-verify.lock`（模拟锁路径无法被创建成文件，例如公共 Git 目录只读，或者那里有同名目录）。然后运行 `bash scripts/ai-verify.sh --spec feat-a`，被 `timeout 8` 杀掉，rc=124。输出是「别的会话正在跑正式验证（进程 未知），等它结束……」。
   - 原因：`until (set -o noclobber; echo $$ >"$LOCK")` 失败后，`pid` 读不出来（为空），既不走「进程已死」分支，也没有别的出口，只会 `sleep 3` 循环。
   - 为什么算关键：改动前这类环境下 `ai-verify.sh` 能正常跑完。现在单工作区、没有任何别的验证在跑时也会无限挂起，违反 AC-07「没有别的验证在跑时不等待」和 AC-01「默认行为不变」。提示还让人去删一个并不存在的锁，误导排查。AI 会话被宿主超时打断后只会重跑，同样卡住。
   - 建议：创建失败后先判断 `$LOCK` 是否是普通文件。不是文件、或者所在目录不可写时，跳过加锁并继续验证，或者明确报错退出。只有锁文件存在并持有进程号时才等待。

## 改进建议
1. `template/.agents/skills/parallel.md:21`：Step 3.5 说「半路放弃的也这样删」，但那条命令里的 `git branch -d` 在分支未合入时会被 Git 拒绝，要用 `-D`。建议在文中写明放弃的分支用 `-D`，否则 AI 会在这一步卡住，或自行想办法。
