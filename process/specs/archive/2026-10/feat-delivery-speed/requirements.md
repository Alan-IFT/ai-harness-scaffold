# 需求与验收规范：feat-delivery-speed

- 创建时间：2026-10-20
- 原始问题 / 原话：「分析为什么前面这个会话耗时这么久？是否有可以减少本套脚手架的需求实现时间消耗的点？」随后用户说「那就按照建议进行修改吧，理论上，这又是一个新的sepc任务吧？」
- 需求分级（象限）：③ 人机协同·复杂度侧；改变验证、状态指纹、门禁和指南，需分切片保持兼容。
- 分级依据：跨模板机制与本仓库自用配置，缩小验证范围可能造成假 PASS。

## 0. 必须明确（四项）
- 做什么：缩短重复验证、返工和状态维护时间，减少可委托验收的等待。
- 为谁做：脚手架项目维护者及跨 IDE 开发 Agent。
- 关键业务规则：G4 仍须完整验证；快速检查不能生成 G4 PASS；缩小指纹范围时须处理未归属改动；②③仅在明确条件委托时可由 Agent 决定 G6。
- 验收标准：见 AC-01 至 AC-06；正反例自检通过并在本仓库完成真实 G4。

## 1. 背景与目标
三个 Spec 的 12 次正式验证共 13 分 45 秒；当前每次自定义检查都运行完整自检。SSOT 审查抓到真实边界错误，应把边界样本前移。状态在 tasks、门禁、度量间重复；全仓指纹受并行任务影响。

- Non-Goals：不取消独立 CR；不让本地记录冒充身份认证；不引入 IDE 专有记忆或平台服务。

## 2. 结构化需求
- REQ-01：WHEN 开发中运行快速验证，THE HARNESS SHALL 执行真实针对性检查且不写 G4 摘要；正式验证仍执行完整检查。
- REQ-02：WHEN ②③进入 G3，THE HARNESS SHALL 要求主要边界样本；G5 仍需独立上下文审查。
- REQ-03：WHEN Spec 有经显式确认覆盖验证依赖的精确文件清单，THE HARNESS SHALL 用清单及必要配置计算状态指纹；无法确认时保守使用全仓指纹；未归属改动不得被静默忽略。
- REQ-04：WHEN 恢复或归档，THE HARNESS SHALL 从 .gates 派生阶段与门间耗时，不在 tasks 维护第二份阶段事实。
- REQ-05：WHEN ②③在 G3 有维护者明确条件委托且 G6 无新增重大风险、AC 全通过、独立审查无阻塞，THE HARNESS SHALL 允许 Agent 记录来源后完成 G6；否则要求当次人的结果决定。
- REQ-06：WHEN ①是简单任务，THE HARNESS SHALL 提供紧凑记录方式但保留 AC、真实验证、独立 CR 与 G6 证据。
- ERR-01：IF 快速检查无真实检查，THEN SHALL 失败且不污染正式摘要。
- ERR-02：IF 清单含不支持的模式或有未归属改动，THEN SHALL 回退全仓或拒绝，不能产生错误 scoped PASS。
- ERR-03：IF 委托缺来源或本次有风险例外，THEN G6 SHALL 拒绝 Agent 自动完成。

## 3. 验收标准（什么算通过、什么算不通过）
| 编号 | 验收点 | 通过条件 | 不通过条件 | 量化指标 / 证据 |
| :-- | :-- | :-- | :-- | :-- |
| AC-01 | 分层验证 | quick 真检查且不覆盖摘要；full 生成 G4 摘要 | quick 伪造 PASS 或 full 被跳过 | 正反例命令与日志 |
| AC-02 | 边界前移 | ②③ G3 缺边界样本拒绝，补齐通过；G5 仍独立 | 空样本可过或取消 G5 | 门禁自检 |
| AC-03 | 指纹归属 | 精确清单隔离无关 Spec 改动；本 Spec 或未归属改动使验证失效 | 无关改动触发重验或漏检 | Git 沙箱正反例 |
| AC-04 | 单一阶段事实 | resume 从 .gates 显示阶段；度量命令从门记录计算 | tasks 必须同步阶段才可接力 | 命令输出和模板检查 |
| AC-05 | 条件委托 | 明确前置授权且客观条件齐全时 Agent 可过 G6；否则拒绝 | Agent 推断人的决定 | G6 正反例 |
| AC-06 | 兼容与简洁 | 旧 Spec 保守路径；①紧凑范例；根脚本薄转发 | 老项目失败或复制机制 | 完整自检与安装样本 |

## 5. 非功能性约束
- 性能：本仓库 quick 不运行约 90 秒的完整自检。
- 安全与权限：本地委托仅作流程证据，强制审批使用代码托管平台。
- 兼容与迁移：旧 Spec 或老项目无精确清单时走全仓指纹；默认验证语义不变。
