## 1. 要做什么
- 做什么：`ai-state-id.sh` 在不能正常读取 Git 仓库的目录里不再给出指纹，改为报错；自检的沙箱改成 Git 仓库，让前 8 节的断言跑在真正的全仓指纹上；活文档记下原因。Git 仓库里算出的指纹值不变。
- 为谁做：第二个 Spec 的前置。现在非 Git 目录里，指纹只覆盖验证目标那一个文件，改别的文件不会让验证过期，和「全仓计算」的说法不符（2026-11-10 实测确认）；Git 因为目录归属等原因读不了仓库时，也会悄悄落到这种只算一个文件的指纹上。自检前 8 节恰好跑在非 Git 目录里。目标参数一去掉，这种目录里就没有任何东西可算，所以要先堵上。
- 不做：
  - 不动 `<file>` 参数、`$TARGET_FILE` 和指纹算法。
  - 不为非 Git 目录另写一套全目录哈希：那里没有忽略规则可用，按接入说明装的项目也不会处于这种状态。
  - 不在 `ai-verify.sh` 开头提前检查能不能算指纹：算不出来时会白跑一次检查命令，但这只在没有 Git 的目录里发生一次，不值得多一次指纹计算。
  - 不改 `ai-resume.sh` 里「尚未初始化 Git 仓库；建议 git init」的提示。
  - 不为缩短自检耗时改夹具：试过把夹具指纹缓存成一个变量，没有测出收益。
