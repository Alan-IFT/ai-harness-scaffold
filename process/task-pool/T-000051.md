### 做什么、为谁做、不做
- 做什么：`ai-state-id.sh` 改成只看文件内容：输出全仓（只排除 `process/` 目录）文件内容的 Git 树哈希。同一份内容，没暂存、已暂存、已提交，指纹都一样。
- 为谁做：换着用不同 AI 工具的维护者。已验证：现在对同一份内容，验证之后再 `git add`，指纹就变了，g2 报「代码在验证后变化」。推断、没有验证：有未暂存改动时，指纹里混着 `git diff` 的文本，两个环境的 Git 配置不同，文本可能不同。
- 不做：不解决 Git Bash 与 WSL 因全局忽略文件不同造成的指纹差异（README 已写明办法：把那些文件写进项目的 `.gitignore`）；不删 `redact()`；不加配置项。

### 依据（2026-11-10 在系统临时目录里实测，原型见下）
- 13 种状态对照。旧算法在三处变值：同一内容从未暂存到已暂存、未跟踪文件到提交、工作区删除到暂存删除。原型这三处都不变。内容变化、新增未跟踪文件、新增 `process-x/` 时原型都变值，`process/` 里的改动不变值；有 `* text=auto eol=lf` 时，同一个文件换成 CRLF 也不变值。
- 不改仓库：运行前后 `git status --porcelain`、`.git/index` 的哈希、`.git/objects` 下的文件数都相同。
- 跨环境：同一个工作目录（含一处未暂存改动、一个未跟踪文件、一个 CRLF 文件），Git Bash（git 2.56）与 WSL（git 2.53）算出同一个值；全新临时仓库的 13 种状态，两边每一行的值都相同。
- 耗时（Git Bash，3 次平均，单位秒；旧算法 / 原型），文件都已跟踪：60 个文件 0.29 / 0.41；5000 个文件 0.36 / 0.61；20000 个文件 0.97 / 1.21；改了 1 个文件时 0.27~0.56 / 0.48~0.51。WSL 下 5000 个文件 0.08 / 0.10。
- 未跟踪文件每次都要重算（方案审查实测）：3000 个未跟踪文件，原型每次 4.4 到 4.7 秒；旧算法同样条件 120 秒内没有跑完。
- 自检：沙箱是 Git 仓库时，把指纹脚本换成原型，现有 76 项断言全部通过，一次测得 80 秒（旧算法同样条件 84 秒）。
- 边界：没提交过的新仓库、项目在仓库的子目录里（只算项目目录内的文件）、链接工作区、带空格和中文的文件名、被忽略的文件、真实索引被锁或不存在，结果都符合预期。未跟踪的嵌套仓库：有提交的按它的 HEAD 计入，错误输出多一行 warning；没有提交的会让 `git add` 失败，指纹算不出来（旧算法是静默跳过）。
- 反面证据：18 个归档 Spec 的提交记录里只有一次重跑验证，原因是审查后改了代码，不是验证与提交的顺序。现有流程是每个任务先提交、全部做完再正式验证，天然绕开了这个坑。Codex、DeepSeek harness 会不会先验证后提交，没有验证过。

### 原型（已按上面的实测跑过；排除 `process/` 的写法按方案审查改过并复测）
```bash
#!/usr/bin/env bash
# 当前代码状态的便携指纹：全仓文件内容的 Git 树哈希，只排除流程记录目录 process/。
# 只看内容：暂存、提交都不改变它；用临时索引和临时对象目录计算，不写真实索引和对象库。
set -uo pipefail

{ read -r objects && read -r index && read -r prefix; } < <(git rev-parse --path-format=absolute --git-path objects --git-path index --show-prefix 2>/dev/null) \
  || [ -n "${index:-}" ] || { echo "状态指纹需要 Git 仓库：先运行 git init" >&2; exit 1; }
tmp=$(mktemp -d) || exit 1
trap 'rm -rf "$tmp"' EXIT
cp "$index" "$tmp/index" 2>/dev/null
export GIT_INDEX_FILE="$tmp/index" GIT_OBJECT_DIRECTORY="$tmp" GIT_ALTERNATE_OBJECT_DIRECTORIES="$objects"
git -c core.safecrlf=false -c advice.addEmbeddedRepo=false add -A -- . ':(exclude)process/' >/dev/null || exit 1
git rm -r -q --cached --ignore-unmatch -- process/ >/dev/null || exit 1
git write-tree ${prefix:+--prefix="$prefix"}
```
实现时还要改三处：
- 开头那句「读三行，读不全又没读到索引路径就报错」写得绕，改成先判断是不是 Git 仓库、再读路径的直白写法，报错的写法与 `feat-t-000049` 定下的一致。
- `git add`、`git rm` 失败时，除了 Git 自己的报错，再补一行说明是在算状态指纹时失败的。
- 排除必须写成 `process/` 而不是 `process`，否则名字恰好叫 `process` 的文件会被漏掉。这是审查发现的，已复现：原写法下改这个文件的内容指纹不变；改成 `process/` 后会变，`process/` 目录照常排除。

### 方案
- `template/scripts/ai-state-id.sh` 整个换成原型的做法，约 14 行（现在 28 行）。几个取舍：
  - 临时索引从真实索引复制，已跟踪的文件能用上 Git 已有的文件状态缓存，只重算变过的；未跟踪的文件没有缓存，每次都要重算。
  - 新对象写进系统临时目录，真实对象库只作只读的备用库，脚本退出时删掉临时目录，不往 `.git` 写任何东西。
  - `process/` 分两步排除：`git add` 时不扫它，再把临时索引里已跟踪的 `process/` 条目删掉。
  - 项目在仓库子目录里时，用 `--prefix` 只取项目目录那棵子树。
  - 没有提交的嵌套仓库让它失败，不加 `--ignore-errors`：指纹算不出来就不算已验证，Git 的报错已经指明是哪个目录；悄悄跳过会漏掉内容。
- `template/scripts/ai-verify.sh`：`verification.md` 的标题行改成「文件内容变化后重新验证；暂存、提交不影响」。
- `template/scripts/harness-selftest.sh` 第 9 节：按 AC-01~AC-03 增加断言，原有「暂存到提交后指纹稳定」并进第一条。
- 文档：`README.md` 的指纹定义改成「全仓文件内容（只排除 `process/`）的 Git 树哈希，暂存和提交不改变它」；`template-mechanism.md`「为什么状态指纹全仓计算、只排除 `process/`」一条补上只按文件内容和用临时索引的理由；根 `AGENTS.md` 第 14 行按需补半句。
- 已排除的方案：
  - 逐个文件 `git hash-object`：纯只读、不用临时目录，但每次都要读全部文件，20000 个文件要 4 秒，冷缓存 45 秒。
  - 不改算法，只在指南里写「先提交再验证」：代价是一句话。这是本条暂缓期间的替代办法。
  - 计算时关掉用户级的忽略文件，让 Git Bash 与 WSL 一致：Windows 这边 AI 工具的本机设置文件一变，验证就会过期。

### 影响与风险
- 依赖可写的系统临时目录和 `mktemp`。Git Bash、WSL、`ubuntu-latest` 都满足。不许写临时目录的沙箱里指纹会算不出来；Codex、DeepSeek harness 的沙箱没有验证过。
- 所有指纹值都会变。升级后进行中的验证要重跑，但任何一次升级都是这样：`scripts/` 本身计入指纹，升级说明第 1 步已经要求先归档在途 Spec。
- 比现在弱的地方：
  - 暂存区不再可见。同一份内容暂存与否指纹相同，这正是本条的目的，但也意味着「索引与工作区不一致」不再反映在指纹里。
  - 子模块只按它的 HEAD 计入，子模块里没提交的改动不改变指纹。
  - 缺少对象的仓库（如部分克隆）里 `git write-tree` 可能失败，指纹算不出来。
- 未跟踪的嵌套仓库行为变了：有提交的从「跳过」变成「按 HEAD 计入」，没有提交的从「跳过」变成「报错」。
- 文件权限位照 `core.filemode` 记录。Git Bash 这边是 `false`，新建的可执行文件记成普通文件；WSL 那边同一个仓库沿用仓库配置，实测同一目录两边指纹相同，但没有专门测过新建可执行文件的情况。
- 仓库路径里带冒号时，Linux 下备用对象库的环境变量会被拆开，指纹算不出来；Windows 的盘符路径和 WSL 的 `/mnt/` 路径不受影响（已实测）。
- 进程被强杀（收不到信号）时，系统临时目录里会留下一个临时目录，里面是这次新算的对象；正常退出和被中断都会清理。
- 指纹不再是 SHA-256 而是 Git 的树哈希（40 位十六进制）。`verification.md` 和 `review.md` 里的值只做相等比较，长度变了不影响门禁。

### 方案审查（2026-11-10，独立 subagent 上下文，只读，三个 Spec 一起审）
- 结论：现在不该做。反面证据是决定性的：18 个归档里没有一次因为先验证后提交而过期；净效果是脚本少十几行，却要加 6 条断言、复测 README 的跨环境说明、把所有指纹换成另一种哈希，原型还有几处缺陷；替代办法只要一句话。建议放弃或暂缓。本条据此暂缓。
- 审查对原型提出的缺陷，都已写进上面的原型说明、验收标准和风险里：名叫 `process` 的文件被漏掉（已复现并改掉）；「只重算变过的文件」对未跟踪文件不成立；`git add`、`git rm` 失败时没有说明；备用对象库路径带冒号的问题；强杀后留下临时目录。
- 审查指出原稿把「验证后再 `git add` 就会过期」和「`git diff` 文本随配置变」都当成事实写。前者有 13 种状态对照的实测，后者只是推断，已在「为谁做」里分开标明。
- 审查核对无误：真实索引被锁、索引不存在时结果不变；并发运行互不影响；「需人决定：是」判得对。
- 审查没有核对：WSL 下的行为与两边一致的说法（这部分是起草者自己测的）、子目录项目、`core.filemode`、稀疏检出与部分克隆、Codex 与 DeepSeek harness 的沙箱。
