# 需求入口与处理决定

> 在创建 Spec 前保留提出者的原始问题，避免多轮转述后只剩实现猜测。这里是轻量收集池，不是新的审批门。清楚的小任务可以直接建 Spec，并在需求来源里引用原话；不需重复抄写。

| ID | 提出时间 / 来源 | 原始问题或原话 | 期望结果与证据 | 处理决定与理由 | 后续链接 |
| :-- | :-- | :-- | :-- | :-- | :-- |

新需求用 `R-001` 起递增 ID，长原话可以链接项目内文件。每行只写原意、期望结果和一次处理决定；完整规则进入 Spec。

处理时先复述理解、追问歧义，再记录决定。产品价值、优先级和是否投入由人判断；AI 可整理选项与证据。④类任务在这里记录人工移交，不进入自动开发门。完成后把后续链接指向 Spec 或决定记录；不要在这里维护第二份完整需求。
