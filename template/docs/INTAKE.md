# 需求入口与处理决定

> 在创建 Spec 前保留提出者的原始问题，避免多轮转述后只剩实现猜测。这里是轻量收集池，不是新的审批门。清楚的小任务可以直接建 Spec，并在需求来源里引用原话；不需重复抄写。

| ID | 提出时间 / 来源 | 原始问题或原话 | 期望结果与证据 | 一次处理决定与理由 | 关联 Spec ID |
| :-- | :-- | :-- | :-- | :-- | :-- |

新需求用 `R-001` 起递增 ID，长原话可以链接项目内文件。每行只写原意、期望结果、一次处理决定和稳定 Spec ID；完整规则进入 Spec。

处理时先复述理解、追问歧义，再记录决定。产品价值、优先级和是否投入由人判断；AI 可整理选项与证据。④类任务在这里记录人工移交，不进入自动开发门。创建 Spec 后填其目录名作为稳定 ID，例如 `feat-user-export`；用 `bash scripts/ai-gate.sh status feat-user-export` 查当前位置和门状态。归档时不改写这一行的 active/archive 路径或完成状态。
