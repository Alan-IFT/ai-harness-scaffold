## 2. 结构化需求 (EARS Acceptance Criteria)
> 采用 EARS 语法，确保每一条可直接转成自动化测试。
> 保留稳定的 REQ / ERR 编号。②③需求把数字上限、禁止项、互斥条件等容易转述走样的原文摘成下方锚点；没有这类细则时写「无」和核对依据。

### 2.1 正常流 (Happy Paths)
- **REQ-01**: WHEN [触发条件], THE SYSTEM SHALL [确定性的系统行为与输出].
- **REQ-02**: WHILE [处于某种状态], WHEN [触发条件], THE SYSTEM SHALL [系统行为].

### 2.2 异常与边界流 (Edge Cases & Error Handling)
- **ERR-01**: IF [非法输入/异常条件], THEN THE SYSTEM SHALL [返回特定错误码/回滚，且不产生副作用].
- **ERR-02**: IF [并发/重试/超时], THEN THE SYSTEM SHALL [幂等或明确失败语义].
